# Проверка доступа к рабочему месту

Не смотри diff и не начинай с поиска по словам «auth», «jwt», «cookie». Сначала открой код сайта и API как человек, который хочет понять, может ли посторонний увидеть документы поставки.

Контекст: это внутренний сервис брокера. На нём разбирают инвойсы, пакинг и спецификации и хранят историю загрузок. Документы не должны открываться без учётки. Регистрации с улицы нет.

Проверь поведение и напиши, где оно ломается. Ожидание такое:

- Без входа нельзя открыть рабочее место, историю поставок, файлы и прочие API с данными. Страница входа отдельная, в рабочей шапке нет кнопки «Войти». Внутри есть кто вошёл и «Выйти».
- Пароли не лежат открытым текстом. Сессия переживает короткое обновление страницы и гасится на сервере при выходе и при блокировке.
- Есть рабочие и администраторы. Администраторов может быть несколько, они равны. Учётку нельзя удалить, только заблокировать. Последнего активного администратора заблокировать или лишить прав нельзя. Пароль от 5 любых символов задаёт только администратор. Логин может быть похож на email (латиница, цифры, @ . _ + -).
- Рабочий видит только свои поставки. Администратор видит все, может открыть и править чужую. Старые поставки без автора видны администратору и выглядят тусклыми, с пометкой что автор неизвестен.
- Журнал действий видит только администратор. В нём логин, не внутренний id. Неудачный вход в журнал не попадает. Событие по поставке появляется после обработки, а не когда файл сняли крестиком до кнопки «Обработать». У карточки есть счётчик, по клику раскрываются детали (сохранение версии, скачивание архива, удаление файла или поставки). Есть фильтры: логин, период (свои даты и готовые интервалы вроде месяца), название или номер инвойса. Из карточки можно перейти к поставке.
- Параллельное сохранение истории по-прежнему не затирает чужую версию молча.
- Экраны входа, шапки и админки читаются на узком экране.

Первого администратора заводят командой на сервере, пароль в репозиторий не коммитится.

Напиши: что выполняется, что нет, и чем это подтверждается (запрос, тест или кусок поведения), без пересказа реализации по файлам.
