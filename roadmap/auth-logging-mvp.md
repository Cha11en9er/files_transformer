# Auth + логирование (MVP)

Доработка хвоста 1-й части и задел пункта 2 второй части ТЗ.  
Сайт с серьёзными документами: без сессии ничего не открывается.

## Зачем

Сейчас сайт и история общие, без учёток. Нужны нормальные пользователи (не один пароль на весь сайт) и журнал действий.

## Вход и безопасность

- Без логина закрыты `/`, `/history`, API и файлы поставок. Отдельный экран входа (не модалка поверх данных). Кнопки «Войти» в рабочей шапке нет.
- Внутри: кто вошёл + «Выйти».
- Регистрации с улицы нет. Пользователей создаёт только админ.
- Пароли только хешем (не plaintext). Сессия как у обычных браузерных приложений (access + refresh или httpOnly cookie), выход и на клиенте, и на сервере.
- Неудачный логин - только серверный лог, в «Историю действий» не пишем.
- Пароль: от 5 символов, любые (хоть `11111`). Задаёт и меняет только админ; обычный юзер сам пароль не меняет. Админ может сменить пароль себе и другому пользователю (в т.ч. другому админу).
- Логин: латиница, цифры и символы в духе email (`@`, `.`, `_`, `-`).
- Первый админ: bootstrap-команда на сервере (пароль генерируется, в чат/git не светить). Путь хранилища - настройка в `.env` (`AUTH_ROOT` и т.п.), сами учётки не в git.

## Роли

- **Рабочий** - обычный сайт: загрузка, разбор, **своя** история поставок.
- **Админ** - то же распознавание + в шапке кнопки «Пользователи» и «История действий». В истории **поставок** видит **все** записи, может **редактировать** чужие.
- Админов может быть несколько; админ может создать другого админа с теми же правами.

## Пользователи (админка)

- **Учётку удалить нельзя.** Вместо удаления - блокировка / разблокировка.
- Заблокированный сразу теряет сессию. Его поставки остаются и видны админу.
- В старых логах логин остаётся; у заблокированного строка тусклая.
- **Нельзя оставить сайт без админа:** нельзя заблокировать (и нельзя снять админ-права) с **последнего активного админа**. Остальные админы между собой равны; одного админа другого заблокировать можно, пока активный админ ещё есть.

## История поставок

- У рабочего - только свои.
- У админа - единый список всех.
- Старые записи до авторизации (без автора): показать админу с пометкой вроде «неизвестно», тусклым.

## История действий (аудит)

- Видит **только админ**.
- В ленте показываем **логин**, не id.
- Событие появляется **после «Обработать»** (поставка уже создана). Снять файл крестиком **до** обработки - в аудит не пишем.
- После разбора и в истории: удаление файла / записи - в аудит пишем.
- Лента не раздуваем: у события по поставке индикатор/счётчик; клик раскрывает детали вниз (сохранил версию, скачал ZIP и т.п.).
- Ссылка ведёт на страницу этой поставки (админ открывает и чужую).
- Фильтры с старта: логин; период дат (свои границы + пресеты вроде «месяц»); название поставки **или** номер инвойса.

## Отказоустойчивость

- Очередь разбора и optimistic save истории (409) сохраняем.
- API и файлы проверяют владельца: рабочий - только своё, админ - всё.
- Аудит писать так, чтобы не терять событие при параллельных запросах.

## Хранение

- Отдельного сервера БД нет: файловое хранилище рядом с данными сайта (допустим SQLite-файлы рядом с `history.db` - это тоже файл на диске).
- `AUTH_ROOT` (или рядом) для пользователей/сессий; аудит рядом или в том же корне.

## Дизайн

- Адаптив: логин, шапка, админка, таблица логов на узком экране.
- Админские разделы - отдельные URL, рабочему не светятся.

## Открытый вопрос заказчику

- Срок хранения аудита: без автоочистки (как файловая история) или N дней (например 90)?

## Вне MVP (не сейчас)

- Полный набор ролей из п.2 ч.2 (аналитик / эксперт / руководитель).
- Схемы выгрузки, шапка/подвал, смена пароля самим юзером.
